# XcpCam

一个 Dalamud 插件：在 GPose 里把镜头（例如 Brio 的各个相机）作为节点摆在一条**按帧计时的相机时间轴**上，生成平滑运镜，可以导出为 XAT `.xcp` 相机文件，也可以直接联动 Brio 的灵动时间轴（Vivacity）。插件会在游戏画面里显示运镜路径和每个镜头，选中的镜头可以直接用变换手柄拖动、旋转。

> 版本：**0.0.6.1 · Pre-release**。在 0.0.6.0 的基础上新增独立的「约束」页与 Blender 风格的追踪约束（阻尼追踪 / 锁定追踪 / 标准追踪）：追踪指定角色的指定骨骼，支持画面偏移、影响、保持取景大小，可与跟随路径同时使用，并可录制目标轨迹用于导出。发布构建通过离线回归；部分游戏内交互仍需继续测试。

## 用法

1. 进入 GPose。镜头节点和曲线都使用**世界坐标**；只有导出 `.xcp` / 联动 XAT 时才按当前选中的 GPose 目标换算为相对坐标（这时需要选中目标）。
2. 输入 `/xcpcam` 打开面板。
3. **相机时间轴**页：
   - 在 Brio 中摆好一个镜头，把播放头移到想要的帧，点 **添加镜头关键帧**（开启「预览镜头」时也能用，抓取的是当前预览或暂停时调整后的画面）；也可以点 **追加到末尾**，自动排在最后一个镜头之后。
   - **从运镜生成关键帧**：播放头必须位于当前轨道某个节点到下一节点的运动区间内部；按当前采样姿态插入节点，同步创建七通道键和时间锚点。为保持一节点一关键帧，停留/解绑等情况下插入可能影响邻近曲线，不保证任意情况下完全保形。
   - 在时间轴上**拖动 ◆ 节点**改变到达时间，精确到帧；手工固定路径不变，仍处于自动状态的贝塞尔切线会按新帧间隔协调；节点只能在相邻节点之间移动，不能越过、重排或占用其他节点帧。若压缩时间导致进度关键帧碰撞，整次移动会被拒绝。点击空白处移动播放头；滚轮平移，Ctrl+滚轮缩放，中键拖动。
   - 时间轴的帧率默认**跟随 Brio 灵动时间轴**。帧率改变时，节点会自动换算，保持原来的秒数不变。
   - 选中节点后，可以在下方面板精确修改：所在帧、停留帧数、硬切，以及位置（世界坐标）、旋转、FoV。曲线插值与手柄改在 **曲线编辑器（Graph Editor）** 中编辑，不再使用节点的旧「经过方式」控制。修改支持撤销 / 重做。
4. **镜头切换（硬切）**：让一段运镜结束后瞬间切到另一个镜头，而不是移动过去。有两种做法，可以混着用：
   - **同一条轨道内硬切**：节点有一个「从上一个节点硬切」开关。节点放在上一个节点之后 1 帧时会自动勾上；手动取消后，就不会再被自动勾上。也可以用「切镜」按钮，抓取当前镜头作为新镜头的起点。切镜不再拆分镜头段：勾选会把前一区间高级七通道和简单三组进度设为恒定，保持前姿态到节点帧再跳变。手动把当前模式全部通道设为恒定也会自动勾选；只改部分通道不标完整切镜，游戏内显示派生虚线相机和连接。取消开关恢复显式切镜前的插值，无记录则使用贝塞尔。
   - **多条镜头轨道**：点「+ 新镜头轨道」添加一条新轨道（放在最上面）。**越靠上的轨道越优先显示**：在上层轨道覆盖的时间里显示上层，上层结束后回到下层。两条轨道交接处就是一次硬切。每条轨道可以上移、下移、静音（M）、独奏（S）、删除。最上面的「输出」行用颜色标出每一段显示的是哪条轨道。
   - 没有任何轨道覆盖的时间段，镜头保持上一个画面不动。
   - 各种输出方式的效果：
     - 预览镜头、烘焙到 Brio 灵动时间轴：完全瞬切。烘焙时，切点处会写成 Step（不插值）关键帧。
     - 导出 .xcp、联动 XAT：.xcp 是 30fps 的连续帧，Brio 播放时会在相邻帧之间插值，所以切点处会有大约 1 帧（33ms）的快速过渡。
5. **游戏内显示与编辑**（同样在相机时间轴页，就在时间轴下方）：
   - 「游戏内显示」：在游戏画面中显示运镜路径和各个镜头的视锥。更多显示选项在「设置」页（也可从 Dalamud 插件列表的设置按钮打开）。
   - 「变换手柄」：选中节点后，游戏画面中该镜头的位置会出现手柄，可以直接拖动来移动或旋转镜头。支持本地坐标 / 世界坐标，以及按步长吸附。节点只能在目标周围的**移动限制**（默认 2000 米，可在「设置」页调整）内移动，单帧跳动过大的拖动会被忽略。
   - **多选镜头组合**：选中多个节点时，面板只编辑组合中心位置，拖动会整体平移所有选中镜头；游戏内手柄放在中心且只能平移。旋转和 FoV 需单独选中一个节点调整。
   - **影响范围**（时间轴传输栏，fps 右侧）：修改节点位置时，默认只重算与该节点相连的两段路径；调大数值会同时重算两侧相应数量的相邻节点。
   - **Delete** 删除选中节点（窗口获得焦点且未在输入文字时）；曲线编辑器和相机时间轴单击空白处取消选择。
   - **总长**：绑定灵动时间轴时与 Brio 的帧长度双向同步；绑定动画进度条时等于动画长度，不能手动修改。
   - **游戏内点选**：在游戏画面中单击镜头节点选中，Ctrl+单击加选 / 取消，单击空白处取消选择。
6. **曲线**页（参照 Blender 的曲线物体与编辑方式）：
   - **添加**：贝塞尔曲线、贝塞尔圆环、路径（NURBS，5 点 5 阶端点）。添加在当前游戏镜头前方 3 米，平放在地面平面上。
   - **物体模式**：变换手柄整体移动 / 旋转 / 缩放曲线；面板可精确输入位置、旋转、缩放。
   - **编辑模式**：把变换手柄目标切到「曲线」后，在游戏画面中点选控制点（方块）或贝塞尔手柄（圆点），Ctrl+单击多选，单击空白处取消；移动 / 旋转 / 缩放围绕所选中心。手柄颜色同 Blender：自动黄、矢量绿、对齐粉、自由深色；拖动自动手柄会变为对齐，拖动矢量手柄会变为自由。
   - **编辑操作**：挤出（从端点延伸）、细分（保持形状）、删除点（Delete 键亦可）、切换闭合、切换方向、手柄类型、倾斜、半径、分辨率，NURBS 的阶数与端点。
   - **节点路径**：由镜头节点生成的默认路径本身就是一条自动（Auto）手柄的贝塞尔曲线，控制点就是镜头节点。在曲线页选中「节点路径」后，可在游戏内拖动节点处的手柄调整曲率，或设置手柄类型。
7. **约束**页（参照 Blender 的物体约束，作用于所选镜头轨道，自上而下求值；相机时间轴页只显示一行摘要）：
   - **追踪约束**：阻尼追踪（最短旋转对准目标，保留节点自身滚转）、锁定追踪（只绕锁定轴转动，默认 Y：只左右摇镜）、标准追踪（对准目标且保持向上轴朝上，不滚转）。可以添加多个，调整顺序、启用、影响（0–1）。
     - 目标：选择角色（默认「当前 GPose 目标」，也可选 GPose 中的其他角色，包括 Brio 生成的）和骨骼（常用骨骼排在前面，可搜索），可加世界坐标的目标偏移。
     - **画面偏移**：目标在画面中的位置（0,0 为中心，±100% 为画面边缘），例如把角色放在三分线上。
     - **保持取景大小**（可选）：按相机到目标的距离自动调整 FoV，目标在画面中的大小保持在轨道首节点时的样子。
     - 追踪约束接管旋转（开启保持取景大小时还接管 FoV，首节点 FoV 仍可调整作为基准）：检查器的旋转 / FoV、游戏内旋转手柄、高级曲线的偏航 / 俯仰 / 滚转（FoV）数值都不能手动修改；添加 / 替换镜头关键帧也不写入这些值。
     - 可以和跟随路径同时使用：跟随路径决定位置，追踪决定朝向。游戏内会在目标处显示标记和瞄准虚线。
     - **录制目标轨迹**：骨骼随动画移动，而导出是离线计算的。点「录制目标轨迹」会从轨道首节点到末节点播放绑定的灵动时间轴 / 动画进度条，逐帧记录骨骼位置；导出 .xcp、联动 XAT 与烘焙使用录制结果。未录制或录制过期（改了角色 / 骨骼、轨道范围变长）时按目标当前位置计算并提示。预览镜头始终实时追踪（预览时每帧同步，暂停时也不能自由旋转被约束的视角）。
   - **跟随路径**：选择一条曲线后，相机位置沿曲线运动（Blender 跟随路径约束，按节点关键帧的固定位置方式）。
     - 位置只由节点在曲线上的**路径进度**决定：首节点 0%、末节点 100%，其余按帧均分；快慢仍可用简单曲线调整。在相机时间轴抓取 / 替换镜头时只写入旋转与 FoV，不受玩家相机位置影响。检查器可直接输入路径进度，游戏内拖动节点会沿曲线滑动，这两种手动设置会保留；「路径进度按时间均分」恢复自动分布。
     - 「跟随曲线」让相机朝向随曲线方向转动（可设前进轴 / 向上轴，曲线倾斜控制滚转）；「使用半径」按曲线半径缩放位置偏移。
     - 编辑目标曲线会立即改变运镜；移除约束或删除曲线时，节点保留当前位置并回到节点路径。
8. **曲线编辑器（Graph Editor）**：同一页面选择 **高级曲线 / 简单曲线**，两种模式互斥编辑，未激活层锁定但保留。高级模式直接读取数值曲线，手柄、斜率和节点帧直接决定速度，不叠加简单缓动或位置等距重参数化。简单模式保留高级路径，只调整节奏。首次从高级切到简单采用中性映射保持当前运动；再次切换保留已编辑的简单节奏，播放结果可因模式不同而不同。切换不重建高级数据，模式状态可撤销。
   - **高级曲线：按 Blender 跟随路径分层**。路径形状只由游戏内的 3D 曲线决定；高级曲线中的位置改为**路径进度**（沿路径的长度比例 0–1，横轴为帧，相当于 Blender 跟随路径的偏移系数逐节点打关键帧）和**位置偏移 X / Y / Z**（叠加在路径点上，世界坐标米，三条通道手柄独立）。路径进度线性时沿路径匀速。节点路径上进度数值由节点位置决定，只能调手柄改变快慢；跟随曲线时可上下拖动改变节点在曲线上的位置。**偏航 / 俯仰 / 滚转、FoV** 保持原有编辑方式。不再按路径参数编辑 X/Y/Z 形状。每个通道每个节点恰好一个键，横轴统一跟随节点帧。
   - 空间层横轴为**相机时间轴帧数**，纵轴默认显示所选项真实数值（位置米、旋转/FoV度）；可选归一化叠加显示。关键帧、手柄、命中与拖动共用帧映射，内部稳定几何参数仅用于避免重定时改变路线。关键帧横移会重定时对应相机节点，所有通道同步；纵向数值与手柄仍可独立编辑。
   - **默认贝塞尔自动路径**：位置路径的自动手柄使用 Blender 曲线的三维 Auto 公式（BKE_nurb_handle_calc），在节点处平滑通过；旋转、FoV 通道新节点默认Auto而非AutoClamped。切线按切镜/停留之间的整段节点和真实帧间隔协调，普通中间节点不强制停顿；明确选组应用手柄时只计算连续选中组，外部手柄不变。手工拉过的手柄不自动重写；仍自动的切线可随节点重定时更新。因此自动路径在重定时时可能改变邻域形状，手工固定曲线则保持。恢复七通道贝塞尔曲线默认生成，不再自动拟合0.0.4.0的Catmull–Rom/SQUAD/Hermite输出，也不生成大量拟合键。插值为贝塞尔/线性/恒定，手柄模式单独设置；保留线性预设和帧数—数值坐标系。
   - **简单曲线：沿路径怎么走**。显示整条轨道，硬切也不拆分编辑段；不受单个运动区间限制。横轴为绝对播放帧，纵轴为整段进度（位置按累计弧长）。镜头节点是到达锚点，可从相机时间轴同步多选；未选节点仍参与运动。进度不能倒退或过冲。
   - **默认按时间平滑**：沿用旧版 Timed 的整段单调 Hermite 速度计算，并转换成可编辑贝塞尔手柄。整段首尾缓入缓出，普通中间节点平滑通过，不逐节点停顿；尊重到达时间，所以任意节点时距不承诺严格匀速。手工编辑不会被同步重建覆盖，可用「恢复按时间平滑」明确重置。
   - **视图导航**：Ctrl+滚轮只缩放横轴；Ctrl+Alt+滚轮只缩放纵轴；Alt+滚轮上下平移；普通滚轮横移。空白左键或中键拖动平移，Shift空白拖动框选，标尺拖动播放头/游标。相机时间轴固定260像素视口，轨道内部滚动；纵向缩放调整轨道行高，不撑高窗口。
   - **多选节点**：Ctrl/Shift 单击切换选择，按住修饰键拖空白框选；拖动已选节点整体平移同轨道选中组，碰撞或越过邻居时整体拒绝。主选姿态仍单独用于数值和 gizmo，批量删除有明确数量提示。
   - **默认联动**：每个区间共享一条运动进度曲线，让位置、旋转和 FoV 同步到达。**解除联动**后可分别编辑 Position（位置） / Rotation（旋转） / Fov（视场角）的进度；解除本身不改变逐帧姿态，之后可调整各组节奏而不改写空间层。重新联动时选用其中一组作为共享进度。
   - **插值与速度**：空间层的手柄控制「路径参数 → 数值」，时间层的手柄控制「播放帧 → 进度」。线性时间进度使位置沿 XYZ 联合定义的几何区间按近似弧长匀速运动，不保证跨区间速度相同、旋转角速度恒定或节点处速度连续。空间层线性并不单独决定播放速度。
   - 支持关键帧选择、显示 / 隐藏、锁定、缩放适配、插值预设与撤销 / 重做；隐藏不等于锁定。同一曲线不能有重复横轴位置。时间层节点锚点可横向重定时，纵向到达进度由空间层决定；曲线页添加关键帧会同步添加相机节点，删除关键帧会同步删除节点及所有通道键；时间图按节点身份去重显示。插值合并为贝塞尔 / 线性 / 恒定；自动钳制 / 自动 / 对齐 / 自由 / 向量作为独立手柄模式，仍受进度约束。恒定插值保持当前值或进度，到下一关键帧跳变；它不是镜头硬切标记，也不能消除输出格式的插值限制。
   - **旋转与 FoV**：空间层使用未折返的 Euler 度数，可编辑 360°、720° 等完整圈数，采样后再合成四元数。俯仰接近 ±90° 时存在 Euler 奇点，抓取或重新写入节点旋转可能出现角度耦合。FoV 空间值以度编辑，实际输出限制在 1°–175°；原始数值和手柄不因输出钳制而被改写。
   - **节点与停留**：节点对应空间层的姿态锚点；节点面板和游戏内手柄只更新选中的位置 / 旋转 / FoV 组，不重写时间曲线。节点停留共同冻结位置、旋转和 FoV，最多持续到下一节点；剩余时长继续沿相同空间路径前进。
   - **插入与重定时**：空间页、时间页和「从运镜生成关键帧」统一创建镜头节点，在该帧取当前组合姿态。严格保持各通道键数等于节点数；停留、解绑或原有独立键需要规整时，插入可能影响邻近曲线，不承诺任意情况下无损保形。已有节点帧只选中，不重复添加。节点移动与 fps 换算仅修改实际时间和进度手柄的时间坐标，保留空间参数、数值和手柄。若整数帧舍入造成节点或进度关键帧碰撞，操作整体拒绝，不合并或丢失关键帧。
9. 预览：
   - 在时间轴上播放或拖动播放头，游戏画面中的绿色视锥会沿路径移动。
   - 也可以勾选时间轴下方的 **预览镜头**，让 Brio 当前的自由相机直接显示这一帧的画面。暂停时可以自由旋转视角、调整 FoV，播放或移动播放头时重新同步到运镜。
10. 输出方式（任选其一）：
   - **导出 .xcp**：在 Brio 相机编辑器中选择 XAT Camera，加载文件后播放。
   - **设置**页的 Brio 联动部分，方式 1「联动 XAT」：Brio 时间轴播放到第一个节点所在的帧时，自动从头播放这段运镜。
   - **设置**页的 Brio 联动部分，方式 2「烘焙」：按节点所在的帧写进 Brio 自由相机的时间轴相机轨道，之后拖动、暂停、循环都完全同步，也可以撤销。
   - 还可以让本插件的播放头**跟随**或**驱动** Brio 时间轴。
11. **绑定对象二选一**（设置页的 Brio 联动部分）：
   - **灵动时间轴**：Brio 的 Vivacity 时间轴。方式 1、方式 2 都能用，帧率可以跟随 Brio。
   - **动画进度条**：GPose 目标当前播放的动画进度，也就是 Brio 动画面板里的 Animation Scruber。相机时间轴的第 0 帧对应动画的第 0 秒，按相机时间轴的 fps 换算成帧。
     - 支持：方式 1「联动 XAT」（动画播放到第一个节点所在的帧时开始运镜，动画循环时会重新开始），以及播放头跟随 / 带动动画进度。
     - 带动动画时可以勾选「拖动时冻结动画」：会通过 Brio 把目标的动画速度设为 0，在 Brio 里重新播放动画即可恢复。
     - 方式 2「烘焙」只能配合灵动时间轴使用。
   - **播放控制**不依赖「播放头跟随」开关：播放/暂停、停止、循环直接作用于所选绑定对象。灵动时间轴的循环与 Brio 双向同步，停止回到 Brio 的 FrameMin；动画模式停止会冻结在动画 0 秒。
   - 动画模式关闭循环后，动画第一次播完会冻结在末尾；再次点播放从头重播。开启循环则跟随动画自然循环。结束范围使用动画自身时长，而不是镜头节点长度。
   - Brio 与相机时间轴帧率不同时，播放位置按秒换算。XAT 播放器本身仍不支持任意跳转/精确暂停续播；需要逐帧同步请使用预览镜头或灵动时间轴烘焙。

## 实现说明

- **抓取**：读取游戏当前正在渲染的相机 `SceneCamera.ViewMatrix`，也就是 Brio 写入的那个矩阵，因此 Brio 的自由相机和普通相机都能抓取。
- **坐标换算**：节点与曲线保存世界坐标；导出 `.xcp` / 联动 XAT 时，按 Brio `CutsceneManager.UpdateCamera()` 的公式换算为当前 GPose 目标的相对坐标（播放时 Brio 以目标为基准，目标移动后镜头跟随）。每次抓取后都会用播放公式重建视图矩阵做自检。
- **曲线**：移植自 Blender（GPL-2.0-or-later）：`curve.cc` 的贝塞尔手柄计算（自动 / 矢量 / 对齐，含 2.5614 长度系数）与 NURBS 求值（均匀 / 端点 / 闭合节点向量，有理权重），`editcurve_add.cc` 的三种原型，`editcurve.cc` 的挤出、细分、删除、闭合与反向，`anim_path.cc` 的按长度比例取点，以及 `constraint.cc` 的跟随路径（路径矩阵 × 相机自身矩阵）。Blender 为 Z 轴向上，原型的 XY 地面映射为游戏的 XZ 地面。节点路径的三维手柄以三条位置曲线存储（手柄横向固定为参数跨度的 1/3），因此与 3D 贝塞尔曲线完全一致；三点共线折返时自动手柄取零长度（Blender 会保留旧手柄）。
- **两层模型**：每条轨道按硬切划分 `ShotCurves`，`Space` 持有七条独立空间数值 `FCurve`，相邻节点之间的 `MotionInterval` 持有时间进度曲线。采样顺序是 **播放帧 → 时间进度 → 稳定空间参数 → 相机姿态**。空间 XYZ 使用联合弧长查表；Euler 角保留未折返度数，再合成四元数；FoV 由空间曲线采样并钳制输出。时间帧、停留及速度不重新生成空间关键帧。改变目标的位置 / 朝向只对最终姿态应用刚体变换，不回写相对坐标。
- **进度模型**：每个区间默认用共享 `FCurve`，解除联动后为 Position / Rotation / Fov 各自的进度曲线。`ProgressCurve` 固定 0 / 1 端点，约束关键帧和贝塞尔有效控制多边形，使进度非递减且有界。贝塞尔通过求解时间坐标求值；线性进度对应当前几何腿的近似等距离运动，不是整条镜头段的统一速度保证。
- **保形与状态**：采样插入同时细分空间参数范围和各组进度，包括原停留映射，不将原有空间曲线按新时间重新拟合。克隆和撤销保留七条空间曲线、独立可变时间曲线以及联动组内的共享关系，恢复后重新绑定节点的空间锚点；节点姿态显示从空间层读取。节点移动、fps 换算先验证全部受影响区间，时间碰撞时整体拒绝。
- **采样与合成**：先将帧号经停留和进度映射到固定几何，再按轨道优先级合成。预览、路径显示、烘焙与导出共用该模型；调节进度不改变硬切边界、节点几何或轨道覆盖范围。无覆盖区间保持前一个完整姿态。
- **输出限制**：`.xcp` 和 Brio 烘焙输出的是采样后的相机姿态，不保存节点几何、联动关系、进度曲线或手柄供下游继续编辑。硬切仍遵循上文区别：预览及带 Step 的灵动时间轴烘焙可瞬切，30fps `.xcp` / XAT 在 Brio 相邻帧插值下约有 1 帧过渡；进度的「恒定」插值不能消除该格式 / 播放器限制。
- **Brio 联动**：Brio 没有提供时间轴或相机的 IPC，所以通过反射访问 Brio 内部。所有用到的成员名都集中在 `Brio/BrioBridge.cs`，找不到成员时只禁用对应功能，不会崩溃。已在 Brio 0.8.0.12 上核对过。
- **文件格式**：`"XCP1"` + uint32 帧数 + 每帧（pos xyz、rot xyzw、fov），小端序，30fps。Brio 的读取代码会少读最后一帧，所以文件头写入 N+1，并在末尾重复写一次最后一帧。

https://raw.githubusercontent.com/MWangLF/XcpCam/main/repo.json

## 构建

需要 .NET 10 SDK 和 XIVLauncher / Dalamud（API 15）。

```
dotnet build -c Release
```

如果 Dalamud 不在默认位置（例如国服），请先设置 `DALAMUD_HOME`：

```
set DALAMUD_HOME=%APPDATA%\XIVLauncherCN\addon\Hooks\dev\
```

将 `bin/Release/XcpCam.dll` 添加到 Dalamud 设置 → 实验性功能 → Dev Plugin Locations。

离线测试（不需要游戏）：

```
cd Tests
dotnet run -c Release
```
